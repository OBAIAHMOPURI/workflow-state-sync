# Team Collaboration Handbook — Workflow State Sync

Start with the [main README](README.md) and its [Related Projects directory](README.md#related-projects). This handbook is a simple guide for conversations and handoffs, not an instruction to write code or operate a live service.

## Purpose and Current Stage

Workflow State Sync explores how different teams or tools could keep an agreed view of a task's progress. A future service could help compare updates, decide which information takes priority, and flag disagreements that need a person's attention.

**Current stage:** a documented concept, not a working synchronization product. It does not currently connect tools, change records, or run scheduled updates.

## How We Work Together

1. **Agree one small outcome.** Describe the question to answer or the wording to improve in everyday language.
2. **Choose a contact and a reviewer.** Agree these roles with the team; this handbook does not assign people or promise a response time.
3. **Make the request clear.** Explain the audience, the current difficulty, the suggested improvement, and what a good result would look like.
4. **Separate ideas from facts.** Label future possibilities as proposals and keep the README's current-stage warnings visible.
5. **Review before sharing.** Ask the agreed reviewer to check accuracy, privacy, and links before publishing a change or making a new commitment.

## Simple Progress Updates

For each handoff, write four short lines: what is done, what comes next, what is blocked, and which decision needs an owner. Link to the relevant project page. Do not report a demonstration, integration, or feature as working unless it has actually been checked.

## Safe Collaboration

Use fictional examples only. Do not connect live tools, send messages, or collect real information as part of reading this handbook. Keep access credentials and confidential operational notes out of this public repository. If a question involves security, sensitive information, or a live system, pause and ask the owner through an agreed private channel.

## New Teammate Checklist

- [ ] Read the main README and understand the project's limits.
- [ ] Agree whom to ask questions and who will review your contribution.
- [ ] Choose a fictional example or a small documentation task.
- [ ] Write down the next step and any decision that still needs an owner.

For more detailed contribution guidance, see [CONTRIBUTING.md](CONTRIBUTING.md).
